1. Visão geral

A aplicação é uma interface PHP executável como programa desktop ou site. Ela centraliza o cadastro de vestidos, clientes, vendas e aluguéis, além de gerar catálogos compartilháveis. Os dados operacionais são obtidos de uma API remota Node.js/Express no Render, cuja persistência está no PostgreSQL/Supabase.

Fonte de verdade: a API remota e seu banco. Os SQL MySQL deste repositório são dumps locais legados e não representam integralmente o contrato atual.

1.1 Capacidades

  • CRUD de produtos e clientes por API.
  • Upload validado de imagens JPEG, PNG e WebP, até 10 MB.
  • Carrinho em sessão para operações de venda e aluguel.
  • Revalidação de estoque e preços no fechamento.
  • Catálogo público com seleção de produtos, cache e WhatsApp.
  • Login administrativo opcional, sessão segura e proteção CSRF.
  • Atualização automática via GitHub, SHA-256, backup e rollback.

O caminho-base é a pasta da aplicação, calculada a partir do serviço. Renomear a pasta externa do PHP Desktop não muda esse comportamento. Credenciais, dados locais, imagens e configurações protegidas não são substituídos.

4.1 Publicação

powershell -ExecutionPolicy Bypass -File tools/build-update-package.ps1 -Version 1.1.3
git add -A
git add -f releases/toa-toa-1.1.3.zip
git commit -m "Publica versão 1.1.3"
git push origin main

Um envio comum ao GitHub não basta. O número precisa aumentar e o ZIP imutável deve corresponder ao SHA-256 do manifesto.

6. Segurança e configuração

6.1 Controles

  • Chave da API mantida em .env e enviada apenas server-side.
  • Cookies HttpOnly, SameSite=Lax e Secure sob HTTPS.
  • Tokens CSRF para operações mutáveis.
  • Escape HTML, validação de upload e redirecionamento local seguro.
  • Hosts GitHub permitidos, SHA-256, staging, backup e rollback.
  • Certificado CA empacotado sem desabilitar validação TLS.

6.2 Variáveis essenciais

APP_AUTH_ENABLED=false
APP_AUTH_USER=admin
APP_AUTH_PASSWORD_HASH=
API_BASE_URL=https://api-toa-a-toa-2.onrender.com

6.4 Diagnóstico rápido

SintomaAção
Certificado HTTPS inválidoCopiar certificates/cacert.pem e os serviços; reiniciar o PHP Desktop.
API sem dadosConferir URL/chave, cURL, OpenSSL, DNS e firewall.
Atualizador offlineConferir certificado, Zip, escrita em storage e updater.log.
Catálogo sem linkConfigurar PUBLIC_APP_URL HTTPS, não localhost.
Sessão após headersIncluir segurança antes do HTML e salvar PHP sem BOM.

6.5 Limitações

  • Backend e migrações oficiais ficam fora deste repositório.
  • Sem fila offline para alterações administrativas.
  • Carrinho temporário depende da sessão.
  • Catálogo limitado a 100 IDs.
  • Bootstrap e ícones dependem de CDN.
  • Mudanças no executável/PHP exigem redistribuição do PHP Desktop.
